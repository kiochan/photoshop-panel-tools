# Panel Recall · 通用浮动面板召回 0.1.0

独立 Windows x64 原型，移动用户绑定的真实浮动面板，不依赖 Bailey 的 DOM、业务接口或 CEP 通信协议。普通原生面板、CEP、UXP 或其他插件，只有在能暴露为可移动的顶层浮动窗口时，才是本原型的候选；不能保证“所有插件”都支持。

这是从旧的“画面镜像＋后台消息转发”另开的技术路线。旧镜像源码仍在 `src/PanelMirror/`，统一工具保留镜像模式。本工具不会复制插件数据，不转发或模拟鼠标、键盘或数位笔，不注入 Photoshop，不修改窗口父子关系，也不自动拆解停靠栏。

## 使用

需要 Windows x64 和 .NET Framework 4.8；无需 Node.js、.NET 8 SDK、CEP 扩展安装或管理员安装。兼容目标为 PS 2019 及以上，重点覆盖 2019、2020、2025，具体版本和插件均未实机验证。当前只编译，不启动程序或运行测试。

1. 解压整包。启动 `PanelRecall.exe`，保留旁边的 `.config` 文件。
2. 在 PS 中先把需要的插件面板拖成浮动窗口，保持可见、未最小化、未最大化。
3. 选槽位，刷新列表，选择明确的窗口并绑定。也可点“3 秒后绑定指针下的浮动面板”，在倒计时内将指针移到目标面板；Esc 可取消。捕获只读取窗口，不会点击它。
4. `Alt+1～5` 将对应面板移到当前指针旁，松键保持；`Shift+Alt+1～5` 放回。绑定的组合键是桌面全局快捷键，冲突会显示在状态区。
5. 已召回同一面板时再次召回，仅重定位，保留第一次的原始位置。召回另一槽位时，先确认前一个已经放回。
6. 开启“画布点击后放回”时，明确识别到同一 Photoshop 的文档画布主按钮按下才开始放回；点击原生面板、未知布局或其他 PS 进程不触发。也可手动关闭此选项。
7. 普通关闭工具前会尝试放回；如暂时无法恢复，可选“仅退出，保留恢复记录”，下次启动后手动点“放回原位 / 恢复上次会话”。

## 恢复和身份校验

在第一次移动前，记录原始屏幕位置、尺寸、窗口句柄、源 PID、进程启动时间及一个窗口属性标记，写入 `%LOCALAPPDATA%\PanelRecall\return.json` 后才发移动请求。配置槽保存 EXE 路径、窗口类和完整标题，不把缺少会话验证的 HWND 当成长期身份。

同一会话以窗口标记、窗口类、PID 及已持有的进程句柄确认对象；标题变化不立即失去绑定。重启工具后，只有 EXE 路径、类和标题唯一匹配才自动解析槽位；同名有歧义时要求重新明确绑定。

移动与放回先定位、等待 DPI 变化，再确认实际位置。放回时恢复原位置和原尺寸，不激活面板、不移动系统指针；没有改动插件业务状态。源窗口禁用、最小化、最大化、身份变化或位置无法确认时保留恢复记录，不能把请求成功当成已经恢复。原显示器不再存在时，将返回位置约束到现有显示器的可见工作区。

强制结束后，重开工具只提示恢复记录，不会自行操作窗口。恢复仍要求原 PID/启动时间、窗口类和属性标记吻合。确认窗口或原进程已经不存在时，仅清理失效记录，不找一个同名新窗口代替。磁盘写入失败时停止新召回，不静默覆盖未处理的恢复记录。

## 限制

- 停靠面板需先手动浮动；本版不模拟拖拽来自动停靠/取消停靠，放回指浮动窗口原来的位置及尺寸。
- 面板需要自身支持被 Windows 移动；某些自绘容器、不同权限的窗口或插件自己的强制定位逻辑可能拒绝移动。
- 一次只管理一个被召回面板。不要同时用另一个召回工具移动同一窗口。
- 移动不会强制激活或设置全局置顶；建议在 Photoshop 前台使用，其他应用遮挡时不抢焦点。
- 插件弹窗继续由原插件管理，不尝试移动其后续弹出的每个窗口。
- 画布点击使用项目共用的保守原生窗口分类，需要命中 `PSViewC` 并具有明确文档父子链；无法识别时保持，不因失焦或任何 PS 点击就放回。未提供鼠标兼容事件的数位笔驱动仍待适配。
- 使用真实窗口意味着输入仍由原插件直接处理；这不能替代不同版本 PS、数位笔和跨屏 DPI 的实机验收。

## 构建

在项目根目录运行 `npm run build:recall`。使用 Windows .NET Framework C# 编译器，不需要额外 SDK；输出到 `dist/panel-recall/` 和 `artifacts/panel-recall-0.1.0.zip`。构建不会启动工具、安装插件或执行测试。`build-manifest.json` 记录校验摘要、共享原生源码和 `runtimeVerified: false`。

真实窗口定位依据 [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)；按 [GetAncestor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getancestor) 区分浮动顶层容器和停靠子窗口。没有直接套用 WindowPerch 的实现。
